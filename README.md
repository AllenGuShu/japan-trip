# 旅遊紀錄手冊

純前端 PWA，資料存在瀏覽器 localStorage，不需要後端、不需要資料庫。

## 這次新增了什麼

- **交通住宿新分頁（🛫）**：內含三個子頁籤
  - ✈️ 航班：可新增去程／回程／轉機航班，記錄航空公司、班號、起降機場與時間、訂位代碼
  - 🏨 住宿：飯店/民宿名稱、地址、入住退房日期、訂房代碼、電話
  - 🚌 其他交通：租車、火車、新幹線、公車、捷運、渡輪、計程車等，記錄出發/抵達地與時間、確認碼
- **完整行程表**：「行程」分頁上方多了「單日檢視／整趟總覽」切換，選「整趟總覽」會把所有天數的行程一次排開顯示，開頭/結尾自動帶入去程/回程航班、下方附住宿一覽，適合出發前整體檢查或直接用瀏覽器列印
- **Google 地標搜尋（選用）**：新增景點、行程點、住宿時，如果你設定了 Google Maps API 金鑰，名稱欄位會變成即時地點搜尋，選中後自動帶入正確地址，「在地圖開啟」也會直接連到該地標而不是關鍵字搜尋

## 關於 Google 地標搜尋設定（選用，不設定完全不影響其他功能）

1. 首頁右上角有個 🔑 按鈕，點開會出現「地點搜尋設定」
2. 你需要自己申請一組 Google Maps API 金鑰：
   - 到 Google Cloud Console（console.cloud.google.com）建立一個專案
   - 啟用「Places API」與「Maps JavaScript API」
   - 到「憑證」頁面建立一組 API 金鑰
   - **建議設定金鑰限制**：限制成只能在你的 Vercel 網域使用，避免被盜用
3. 把金鑰貼到 App 裡的 🔑 設定，儲存後，新增景點/行程點/住宿時輸入關鍵字就會出現真實地點建議
4. Google 有免費額度，但新帳號需要先綁定信用卡才能啟用 API（即使在免費額度內也一樣），這部分要由你自己在 Google Cloud 完成，超出免費額度才會產生費用，一般個人使用這種頻率不太會超過
5. 沒有設定金鑰完全沒關係，所有地點欄位一樣可以手動輸入文字，「在地圖開啟」會用關鍵字搜尋的方式開啟地圖，只是不會鎖定成 Google 資料庫裡的精確地標

## 部署步驟（GitHub Desktop + Vercel）

1. 用 GitHub Desktop 打開你原本的 repo（同一個，不用建新的）
2. 把這次的檔案（index.html、style.css、app.js、manifest.json、sw.js）覆蓋貼進資料夾
3. Summary 填「新增航班/住宿/交通資訊、完整行程表、地標搜尋」→ Commit to main → Push origin
4. Vercel 會自動偵測並重新部署

## 加到手機主畫面

已經加過主畫面圖示的話**不用重新加**，直接開啟即可。如果畫面看起來還是舊版，把 App 完全關閉（滑掉）再重新打開一次。

## 技術備註

- 拖曳排序（SortableJS）與地標搜尋（Google Maps）都是透過 CDN／外部 API 載入，需要網路連線；離線時仍可查看/編輯已載入過的資料，但這兩項功能會暫時無法使用
- Google Maps API 金鑰存在你這台裝置的瀏覽器 localStorage，不會上傳到任何地方，換裝置需要重新設定

## 尚未做到：真正的多人即時共同編輯

目前仍是純前端＋本機儲存架構，還是無法做到「兩人同時打開、即時看到彼此變動」。如果之後想做，需要另外接雲端資料庫（例如 Firebase），這會是比較大的架構調整，確定要做的話再跟我說。

## 資料保存

所有資料都存在**該台裝置瀏覽器**的 localStorage，換裝置或清瀏覽器資料會遺失。可以用「匯出成檔案」備份，到另一台裝置「匯入」還原。
