# 旅遊紀錄手冊

## 這次修正：日期少一天的問題

### 原因
計算「出發日期 + 第幾天」的函式裡，用了 `toISOString()` 這個方法把日期轉成文字。這個方法有個常見陷阱：**它會先把日期換算成 UTC 標準時間，再輸出**。台灣時區是 UTC+8，所以只要換算後跨過午夜線，日期就會被往前推一天——這就是你明明選 21 號，畫面卻顯示 20 號的原因。跟你操作無關，是計算方式本身的 bug。

### 修正
改成直接讀取日期的年、月、日各別數值組成文字，不再經過 UTC 轉換，就不會再有這個位移問題。已經用台灣時區實際測試過：輸入 8/21 出發、6 天，Day 1 正確顯示 2026-08-21、Day 6 正確顯示 2026-08-26，不會再少一天。

## 部署步驟（GitHub Desktop + Vercel）

1. 用 GitHub Desktop 打開你的 repo
2. 把 app.js、sw.js 覆蓋貼進去
3. Commit to main → Push origin
4. Vercel 自動重新部署

## ⚠️ 重要：舊資料需要手動修正

**這次更新前用「出發日期」自動產生的旅遊，日期可能都少了一天**（因為是被上面那個 bug 算出來的），舊資料不會自動修正。麻煩更新後：

1. 打開受影響的旅遊 → ⚙️ 設定
2. 「出發日期」欄位重新選一次正確的日期
3. 點「套用日期到每一天」，讓所有天數重新用正確的邏輯計算一次

這樣就會修正回來。之後新建立的旅遊就不會再有這個問題了。
