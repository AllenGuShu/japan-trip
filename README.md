# 旅遊紀錄手冊

純前端 PWA，資料存在瀏覽器 localStorage，不需要後端、不需要資料庫。

## 這次新增了什麼

- **整合行程表設為進入首屏**：打開一趟旅遊後，第一眼看到的就是「行程」分頁的「📋 整合總覽」——會自動把當天符合日期的航班、住宿入住/退房、其他交通都顯示在對應那天的行程上方，不用自己對照。「✏️ 單日編輯」則是原本可以拖曳排序、新增行程點的編輯畫面。
  - **重要**：要讓整合功能生效，每天要設定「日期」（單日編輯畫面裡日期改成日期選擇器），航班/住宿/交通資訊也要填上對應日期，系統才能自動比對串在一起。
- **景點快速排入行程**：景點清單每張卡片新增「＋ 排入行程」按鈕，選好日期跟時間，一鍵把景點轉成當天的行程點，不用重打一次名稱
- **天氣預報**：⚙️設定頁新增「天氣查詢城市」欄位（填城市英文/拼音名，如 Tokyo、Osaka），儲存後整合總覽會在每天標題顯示當天天氣圖示與高低溫（使用免費 Open-Meteo 服務，未來 16 天內才查得到，太久遠的行程要接近出發才會有資料）
- **航班/住宿確認信自動辨識（測試版）**：新增航班、新增住宿的表單裡多了「📋 貼上確認信自動辨識」欄位，把訂票網站寄來的確認信文字貼上去，按「自動帶入欄位」會嘗試抓出航空公司、班號、日期、時間、訂位/訂房代碼等資訊。這是關鍵字/格式比對的陽春版，**不保證每次都準確，請務必核對後再儲存**
- **深色模式**：首頁與旅遊內頁右上角新增 🌙 按鈕，可切換深色/淺色主題，設定會記住
- **每日心得/遊記欄位**：單日編輯畫面新增「📝 這天的心得/遊記」欄位，旅遊結束後可以回來記錄當天發生的事，整合總覽也會顯示出來，讓這本手冊真的能當作旅遊紀錄回顧

## 部署步驟（GitHub Desktop + Vercel）

1. 用 GitHub Desktop 打開你原本的 repo（同一個，不用建新的）
2. 把這次的檔案（index.html、style.css、app.js、manifest.json、sw.js）覆蓋貼進資料夾
3. Summary 填「整合行程表、快速排入行程、天氣、確認信辨識、深色模式、遊記」→ Commit to main → Push origin
4. Vercel 會自動偵測並重新部署

## 加到手機主畫面

已經加過主畫面圖示的話**不用重新加**，直接開啟即可。如果畫面看起來還是舊版，把 App 完全關閉（滑掉）再重新打開一次。

## 舊資料相容性

之前建立的旅遊，天數的「日期」欄位如果是自由輸入的文字（例如「8/29 (六)」），改版後會變成日期選擇器，這些舊文字不會被自動轉換，需要手動重新選一次日期，之後整合功能才抓得到。航班/住宿的日期比對也是同樣道理——都是新欄位，需要重新填一次日期才會出現在整合總覽裡；其他資料（航班基本資訊、住宿名稱等）都完整保留，不會遺失。

## 資料保存

所有資料都存在**該台裝置瀏覽器**的 localStorage，換裝置或清瀏覽器資料會遺失。可以用「匯出成檔案」備份，到另一台裝置「匯入」還原。

## 尚未做到：真正的多人即時共同編輯

目前仍是純前端＋本機儲存架構，無法做到「兩人同時打開、即時看到彼此變動」。如果之後想做，需要接雲端資料庫（例如 Firebase），是比較大的架構調整，確定要做的話再跟我說。
