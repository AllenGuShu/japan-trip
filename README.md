# 旅遊紀錄手冊

純前端 PWA，資料存在瀏覽器 localStorage，不需要後端、不需要資料庫。

## 這次新增了什麼

- **預算功能**：⚙️設定頁可設定總預算與各類別（交通/住宿/餐飲/門票/購物/其他）預算，記帳頁會顯示進度條，接近/超過會變色提醒
- **景點標籤**：新增景點時可勾選標籤（美食/購物/自然/文化/歷史/夜景/親子/秘境/打卡），景點清單可依標籤篩選
- **行程拖曳排序**：每日行程的站點卡片左上角有 ⠿ 拖曳把手，長按拖曳可自由調整順序（不再強制依時間排序，時間欄位僅顯示用）
- **複製旅遊範本**：首頁每張旅遊卡片右上角「⋯」可以「複製（含所有資料）」或「複製為範本（清空行程與花費，保留準備清單/例句/國家設定）」
- **匯出/匯入（非即時協作）**：
  - 首頁卡片「⋯」或旅遊內的 ⚙️設定 都能「匯出成檔案」，存成一個 `.json` 檔
  - 首頁「📥 匯入旅遊檔案」可以把別人傳給你的檔案讀進來，變成手冊裡新的一趟旅遊
  - 這是**非即時**的分享方式：適合「我先規劃、傳給朋友看/改、他傳一份新的給我」這種輪流編輯，不是兩人同時看到彼此即時變動

## 關於「多人即時共同編輯」

目前這個 App 是純前端、資料存在**你手機瀏覽器本機**，沒有伺服器，所以無法做到「兩個人同時打開、即時看到對方改的東西」。

如果你之後真的需要這個功能，做得到，但需要多一層雲端資料庫（例如 Google 的 Firebase，有免費額度），大概會需要：
1. 你申請一個免費 Firebase 專案（幾分鐘，我可以一步步教你）
2. 把 App 的資料存取從 localStorage 改成連到 Firebase（我來改）
3. 之後同一趟旅遊，多人打開網址、輸入同一組「旅遊代碼」就能一起即時編輯

這算是不小的架構升級，先讓你評估要不要做，確定要的話跟我說，我再幫你規劃步驟。

## 部署步驟（GitHub Desktop + Vercel）

1. 用 GitHub Desktop 打開你原本的 repo（同一個，不用建新的）
2. 把這次的檔案（index.html、style.css、app.js、manifest.json、sw.js）覆蓋貼進資料夾
3. Summary 填「新增預算/標籤/拖曳排序/匯出入/複製範本」→ Commit to main → Push origin
4. Vercel 會自動偵測並重新部署

## 加到手機主畫面

已經加過主畫面圖示的話**不用重新加**，直接開啟即可。如果畫面看起來還是舊版，把 App 完全關閉（滑掉）再重新打開一次。

## 技術備註

- 拖曳排序使用開源函式庫 SortableJS（透過 CDN 載入），需要網路連線第一次載入頁面時抓取；之後瀏覽器會快取，離線也能用
- 即時匯率、拖曳排序函式庫都需要網路連線；離線時仍可查看/編輯已載入過的資料，但這兩個功能會暫時無法使用

## 資料保存

所有資料都存在**該台裝置瀏覽器**的 localStorage，換裝置或清瀏覽器資料會遺失。如果想備份或搬到別的裝置，可以用「匯出成檔案」再到另一台裝置「匯入」。
